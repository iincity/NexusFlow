# NexusFlow 外部环境验收测试用例

## 目的与边界

本文用于开发者在**受控正式环境**完成本机无法替代的验收。每次执行应记录执行人、开始/结束时间、目标版本、环境、请求 ID、脱敏日志链接和结论。密钥、数据库连接串、长期 Bearer、Cookie、文件正文和个人数据不得进入本文、截图或 CI 日志。

本机 PostgreSQL/MinIO/mock OIDC、loopback Relay、协议 mock 与构建测试只证明回归和契约；它们**不构成**以下生产或 Pro 验收的批准证据。Hosted CI 目前按项目决定不执行。

## 共用前置条件

| 项目 | 要求 |
| --- | --- |
| 版本冻结 | 记录根仓库、`nexus-tunnel`、RustDesk Client/Server/Pro Web Client 的提交或制品 SHA256。|
| 账号与租户 | 准备 Tenant A、Tenant B、A 的 owner/member/removed-member，均为一次性测试账号。|
| 设备与授权 | 准备 A/B 各一台非生产测试设备；至少一个有效、一个撤销的 bearer/file grant。|
| 证据 | 浏览器 HAR、控制面审计事件、脱敏应用日志、数据库查询结果摘要；严禁原始密钥。|
| 清理 | 撤销全部测试 session/grant，删除测试 Storage 对象和测试用户；确认审计事件保留。|

## A. Supabase 与正式控制平面

### CP-EXT-01：TLS 数据库连接与迁移版本

- 前置条件：获得短时、最小权限的 `DATABASE_URL`（只读）和 `MIGRATION_DATABASE_URL`（迁移角色）；连接仅经正式 TLS 端点。
- 步骤：使用安全凭据存储注入环境变量；验证客户端要求 TLS、证书链与主机名；只读查询当前 schema migration 版本；以迁移角色执行项目的 migration list/验证命令，不执行未批准 migration。
- 预期：TLS 与证书校验成功，schema 版本与冻结版本一致；只读角色不能 DDL/DML，迁移角色范围符合授权。
- 证据/清理：保存版本号、证书 subject/expiry 和脱敏命令输出；立即清除环境变量与临时凭据。

### CP-EXT-02：Auth/OIDC 与 JWT 合约

- 前置条件：正式或隔离的批准 Supabase Auth/OIDC tenant、测试 IdP 客户端和回调地址。
- 步骤：分别以 A-owner、A-member、B-member 完成登录、刷新、登出；校验 JWT `iss`、`aud`、`sub`、过期时间和控制面验证结果；使用过期、错误 issuer、错误 audience 的 token 访问受保护 API。
- 预期：合法 token 可完成其授权操作；三种非法 token 在信任边界被拒绝；刷新/登出后行为符合已定义的 session 失效策略。
- 证据/清理：记录 claims 名称和值的哈希/掩码、request ID 和拒绝状态码；撤销所有 session。

### CP-EXT-03：Tenant A/B RLS 隔离

- 前置条件：A/B 都含设备、隧道服务、路由、审计和 Storage 对象。
- 步骤：以 A-owner/member 调用读取、创建、更新、禁用和审计查询；对 B 的每类资源重复读取/写入/枚举尝试；以 B 重复相反方向。
- 预期：主体只能看到且只能变更所属 tenant 资源；跨租户请求稳定返回禁止/空结果（按 API 合约），不泄漏 ID、对象名、计数或本地地址。
- 证据/清理：每个资源类型至少一条允许与一条拒绝的 request ID/状态码；删除测试资源。

### CP-EXT-04：成员移除与 Bearer 撤销

- 前置条件：A-member 有活动 session、Bearer 和至少一个已签发 tunnel grant。
- 步骤：移除该成员；用其既有 cookie/JWT、Bearer 和 grant 立即及在约定缓存窗口后请求控制面、WebSocket 和 Relay；另撤销一个未移除成员的 Bearer 并重复。
- 预期：移除/撤销后新请求失败关闭；已建立会话按产品约定关闭或在界限内失效；审计包含 actor、对象、原因、时间与 request ID。
- 证据/清理：记录失效时延和审计事件，不保存 token；撤销剩余测试凭据。

### CP-EXT-05：私有 Storage 与 file grant 撤销

- 前置条件：私有 bucket；A/B 各一个测试文件；签名下载或 file grant 功能已启用。
- 步骤：A 上传、下载和（若支持）覆盖 A 对象；B 尝试列举/下载 A 对象；撤销 A 的 file grant 后重复下载；尝试复用过期 URL/grant。
- 预期：A 仅访问 A 范围；B 无法发现或下载 A 对象；撤销和过期均拒绝；覆盖操作具有项目要求的 INSERT+SELECT+UPDATE 授权。
- 证据/清理：保存脱敏对象键、状态码和 audit/request ID；删除对象、签名 URL 与 grant。

### CP-EXT-06：控制面 HTTPS、内部令牌与审计脱敏

- 前置条件：正式 HTTPS 控制面、Tunnel/Relay 内部短时 token、日志检索权限。
- 步骤：执行设备注册、desired-state 获取、route/grant 签发、Relay usage 回报；对缺失/错误/过期内部 token 分别重试；检索对应审计和应用日志。
- 预期：合法调用成功；非法内部凭据在网络边界失败关闭；审计关联 tenant、主体、资源和 request ID；日志不含 service role、数据库密码、完整 bearer、Cookie、私有目标地址或文件内容。
- 证据/清理：导出脱敏日志片段与审计链接；轮换/撤销测试内部 token。

## B. RustDesk Pro 与真实远控数据面

### RD-PRO-01：许可证与制品冻结

- 前置条件：有效 Pro 许可证、批准的 Pro Web Client/WebRelay 发布包，以及已记录的版本/SHA256。
- 步骤：验证许可证激活状态；计算并比对 Web Client/WebRelay SHA256 与冻结 BOM；将一个 hash 被篡改或版本不匹配的制品放入隔离环境启动。
- 预期：正式制品版本和 hash 完全匹配；不匹配制品失败关闭，不进入真实验收。
- 证据/清理：保存许可证状态摘要、版本和 hash；删除篡改副本。

### RD-PRO-02：真实设备配对与浏览器远控

- 前置条件：一台 Host、一台 Remote/管理员终端，均为独立真实设备；浏览器满足 Pro Web Client 支持矩阵。
- 步骤：在控制面完成 Host 注册和批准配对；浏览器登录后选择该设备，建立远控会话；验证画面刷新、分辨率变化、鼠标单击/拖动、键盘输入与剪贴板。
- 预期：仅获授权主体可见设备并连接；画面与输入可用且没有明文控制数据写入应用日志；未配对或撤销设备被拒绝。
- 证据/清理：录制不含敏感内容的短视频/截图、会话 ID、审计事件；结束会话并撤销临时配对。

### RD-PRO-03：文件传输与异常恢复

- 前置条件：可公开的测试文件，小文件和产品要求的最大/大文件样本，已记录 SHA256。
- 步骤：Web Client 向 Host 上传并反向下载；验证 hash；在传输中断开网络/Relay，按产品能力观察超时、取消或续传；使用无权限用户重复。
- 预期：授权传输完整且 hash 一致；中断行为符合产品约定，不产生未授权残留文件；无权限用户被拒绝。
- 证据/清理：记录文件 hash、耗时、会话 ID 与错误码；删除两端测试文件。

### RD-PRO-04：WebRelay、直连/中继与故障切换

- 前置条件：至少两个健康 Relay，允许观测选路且不暴露私网数据。
- 步骤：分别验证可直连、强制 Relay、首选 Relay 不可用后的切换；在每种路径重复 RD-PRO-02 的最小画面和输入检查。
- 预期：会话按策略建立并在可用时切换；无越权连接、无跨 tenant 选路；故障日志和审计可关联会话。
- 证据/清理：记录路径类型、Relay ID（脱敏）、切换时延、会话/请求 ID；恢复 Relay 状态。

### RD-PRO-05：远控与 Nexus Tunnel 隔离

- 前置条件：同一 Host 上存在一个已授权 Nexus Tunnel 服务和一条独立 RustDesk 远控会话。
- 步骤：并发建立远控及 Tunnel 流量；撤销 Tunnel grant，确认远控仍按原授权工作；再撤销设备/远控授权，确认 Tunnel 按其独立授权策略处理；检查审计和带宽/会话统计。
- 预期：两类数据面通道、授权、撤销、计量和审计互不占用、不相互提权；仅共享已设计的注册/控制扩展时也保持协议兼容。
- 证据/清理：保存并发时间线、脱敏 session/grant ID 和两类审计；终止所有会话并撤销测试授权。

## 通过规则与问题报告

每个用例必须有“通过/失败/阻塞”结论。失败报告至少包含：用例编号、冻结版本、环境、可复现步骤、期望/实际、request/session ID、脱敏日志和影响范围。任一跨租户泄漏、凭据泄漏、撤销后仍可新建访问或制品不匹配均为阻断发布的问题。
